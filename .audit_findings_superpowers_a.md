# ANDROID DEEP AUDIT — Lens 3 (Superpowers structured-review methodology) — Part A: UI half

Scope: `app/src/main/java/com/powermediaplayer/ui/` — 66 files, ~1.4 MB.
Batches: P1 player core (PlayerScreen/PlayerViewModel/PlayerUiState) · P2 player/components + ui/components · P3 cloud (CloudBrowserScreen/CloudViewModel) · P4 settings (13 files) · P5 library + lastplayed + smartplaylists · P6 podcast + info + navigation + equalizer + downloads + overrides + theme + stats + adaptive.

Methodology applied per component:
1. **VERIFICATION-BEFORE-COMPLETION** — claimed behaviours (comments, `git log --oneline -- <path>`, TASKS.md) verified against delivered code; claim/code mismatches flagged with evidence.
2. **SYSTEMATIC-DEBUGGING** — failure-mode enumeration (nulls, races, lifecycle, cancellation, config change on the foldable, process death) with concrete failure scenarios for unhandled modes.
3. **PLANNING** — implementation-shape vs problem-shape mismatches (duplicated state machines, hand-synchronised parallel paths) with quantified sync burden.

Objective: code minimisation (footprint, speed, battery, memory, CPU, storage, store acceptance). Every finding carries INTERDEPENDENCE; every removal/change candidate carries PRESERVATION PRE-ANNOTATION ((a) why safe, (b) prior bug defended against per `git log -S` / regression comments, (c) why it cannot recur) or is marked KEEP-DO-NOT-TOUCH.

Status: sections appended incrementally as each batch completes. A batch summary table closes the file.

Reasoning: The other lens claimed "per-line GPU readback". Verdict: PARTIALLY VERIFIED — the true shape is worse in one axis, better in another.
- REFUTED as per-visual-line-per-frame: the per-line pills in FrostedTextLine (CoverFrost.kt:241-291) are pure GPU work — clipPath + drawLayer(f.blurred) + dim rect inside drawBehind. No readback in the draw phase. The two GraphicsLayer.record calls per frame in captureCoverFrost (CoverFrost.kt:101-106) are also GPU-side.
- VERIFIED as per-TEXT-ELEMENT readback: rememberResolvedTextColour (CoverFrost.kt:168-175) runs frost.sharp.toImageBitmap() inside LaunchedEffect(frost?.captured, bounds, palette). toImageBitmap() is a blocking GPU-to-CPU readback of the ENTIRE captured cover layer (up to full-screen: 1080x2520x4 ~ 10.9 MB), executed on the MAIN dispatcher (only averageLuminance is moved to Dispatchers.Default; the readback itself is not). A single track change (palette key changes) therefore triggers 5 full-layer readbacks on the main thread plus up to 5 HARDWARE-to-ARGB_8888 software copies (CoverFrost.kt:112) on Default — ~55 MB transient allocation and 5 GPU stalls per track change.

Interdependence: PlayerScreen provides the frost via LocalCoverFrost (PlayerScreen.kt:387-391); CoverArtBackground is the capture source (843 compact / 1448 expanded — mutually exclusive layouts, so single-writer is safe); PlayerTextColour util consumes the luminance; palette comes from onColorsExtracted.
Preservation: The readback APPROACH is deliberate and documented (CoverFrost.kt:56-65): it reads "what was truly drawn, not the source bitmap + a transform guess" — the defence for the Fit/Crop/zoom/fold legibility bug (user 2026-06-30). Safe minimisation that keeps the defence: (a) sample ONCE per (captured, palette, coverOrigin) into the shared CoverFrost holder (one readback), then derive each line's regional luminance from that single software bitmap keyed by each line's bounds — behaviour identical, readbacks drop 5x to 1x; additionally debounce bounds (snapshotFlow + debounce) so animations sample once at rest. (b) Prior bug defended: illegible text over high-contrast covers + stale colour across track change — both preserved because sampling still uses the real captured layer and still re-keys on palette. (c) Regression cannot recur if the single shared sample keeps the same keys (captured, palette, bounds-at-rest). Anything beyond that (e.g. replacing readback with palette-only guessing) is KEEP-DO-NOT-TOUCH — that is exactly the bug this design exists to kill.
